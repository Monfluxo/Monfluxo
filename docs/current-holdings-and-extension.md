# Verified holdings and history extensions

History progress is keyed to a wallet and follows saved transaction counts, including paused-to-resumed transitions. The extension control is above Analyze wallet, appears only for the loaded incomplete wallet and is disabled while indexing/budget authorization runs. Owner requests use the same endpoint and return zero cost. A successful authorization displays its target; a failure displays the server reason. Polls do not consume credits.

Current token quantities come from confirmed getTokenAccountsByOwner calls for both SPL Token and Token-2022, aggregated by mint with exact raw BigInt amounts. Native SOL uses getBalance. Context slots are retained as a range because parallel requests need not share an exact slot. Failure of either program leaves the portfolio unavailable, never falsely empty. DAS supplies optional metadata/prices; incomplete DAS metadata does not remove balances or substitute its stale quantities. Cached snapshots expire after 30 seconds.

All positive balances are returned. Only 50 metadata lookups per full enrichment are allowed; cached metadata is applied to other balances. Sort runs again after price enrichment. The table renders a bounded number of rows at a time, with search, Show more, and an explicitly named mint-suffix filter (suffix alone is not proof of Pump.fun origin). Pump.fun can apply its own token/dust filtering and prices; the UI does not promise identical valuations or token lists.

A new authenticated wallet request captures balances before authorizing the indexing job, then writes one immutable-in-application compact record after authorization succeeds. The insert ignores duplicate wallet keys. Existing indexed wallets receive first_recorded, with their actual capture time, never a fabricated historical scan_start. Failed snapshot capture prevents initial authorization. A storage failure after successful authorization is logged and returns initialSnapshotSaved:false; it does not report the accepted indexing request as failed. The dashboard shows first-snapshot metadata when available. Raw balances, decimals, native SOL, time and context slots are stored once, without token metadata or transactions. The table has RLS and no browser-role privileges. Wallet purges must also remove wallet_initial_holdings.

Validation: node tests cover both token programs, duplicate accounts, precision beyond Number.MAX_SAFE_INTEGER, >1,000 holdings, missing program results, compact snapshots, polling transitions, retry and unmount. SQL rollback tests verify duplicate capture preservation and private-role access. Next production build validates all modified components.
