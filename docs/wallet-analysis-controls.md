# Wallet admission and analysis budgets

Public beta: default 5,000 processed transactions per incomplete wallet history; administrator may raise the lifetime work allowance up to 50,000. Work is checkpointed with the backfill cursor; repeated dashboard requests do not replenish it. Already complete histories remain readable, with bounded refreshes. Legacy histories without transaction counters use pages * 100 as a conservative workload estimate. This is NOT a billable count of unique transactions.

Helius Wallet Identity is consulted before analysis, persisted for 24h, and manually overridden policies never expire. Known exchanges, programs, validators, stake pools and bridges are blocked. Market makers and trading firms are excluded from rankings while bounded analysis remains available. Unknown wallets with at least 1,000 sampled signatures spanning less than 24h require review; this label does not assert that they are bots. Unavailable or unpaid Identity API access falls back to bounded analysis and a lightweight signature sample. It cannot guarantee that all CEX or bot wallets are identified.

Admin: `/admin`, enter the existing MONFLUXO admin key in the maintenance section, then use **Wallet restrictions & analysis limits**. Check a wallet, choose Block / Exclude / Review / Allow, set a transaction limit and reason, and save. Only the backend admin key authorizes mutations; table and sync-lease RPC are service-role-only. Keys are kept in React state and never added to URLs or local storage. Saving Allow / Exclude requeues paused jobs; insufficient allowance pauses them again. Raising the budget does not override a Block / Review policy.

Both Trade Intelligence and Smart Wallet rankings exclude restricted wallets and incomplete histories. The sync engine checks restrictions between history pages and uses an atomic lease shared by API and worker. A newly saved block stops the next page, not a request already in flight. Supplemental legacy token-account scans are disabled because they bypass unified-history budgeting.

Prepared credit pricing: 3 credits for the first 5,000 new transactions, +1 per additional block of up to 2,000; incremental refresh +1 per block of up to 2,000; zero for no new work; Pro quota 30/month. `analysisBudget.js` exposes the formula with `billingEnabled:false`. No balance is charged, reserved or reset monthly yet: authenticated accounts, an atomic credit ledger, unique-transaction billing, request consent and subscriptions must be integrated first. Work counters must never be billed directly because retries and legacy estimates are not exact unique new transactions.

Verification: pure budget/policy tests and real sync-body integration tests using a simulated 5M history, exact remaining allowance, saved cursor, repeated requests, in-flight block, failed write checkpoint and concurrent lease; SQL rollback verification and backend-only grants; Next production build.
